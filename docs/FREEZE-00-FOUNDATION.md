# FREEZE-00 Foundation

Status: IMPLEMENTATION CANDIDATE — not frozen until automated Windows qualification and interactive Windows runtime qualification both pass for the same candidate bytes.

This gate establishes only shared infrastructure that later product engines depend on. It does not claim Discovery, Query, file actions, document extraction, Teach-by-Example, classification, reporting, or general product UI behavior.

## Locked technical baseline

- C# / .NET 10, SDK 10.0.400
- WinUI 3 through stable Microsoft.WindowsAppSDK 2.4.0
- Windows SDK BuildTools stable 10.0.26100.9169
- SQLite through Microsoft.Data.Sqlite 10.0.11
- Central package management and committed NuGet lock files
- NuGet locked-mode restore and audit enabled
- Warnings as errors and deterministic managed builds
- xUnit v3 4.0.0 with Microsoft.Testing.Platform v2

## Foundation contracts

- Validated operation, engine, capability, error-code, and plan-fingerprint value objects
- Immutable operation plans with exact revision + SHA-256 plan fingerprint binding
- Execution results and operation evidence bound to the exact plan identity, not only an operation ID
- Explicit fail-closed operation-state transition contract from Planned through Verified/Committed or failure/review paths
- Structured errors and typed result contract
- Engine identity, capability declaration, and qualification contract
- Append-only concurrent-safe JSONL evidence writer
- Golden Corpus manifest model and JSON schema with path, hash, uniqueness, and expected-result invariants
- Real SQLite Foundation database with schema versioning, WAL verification, foreign-key enforcement, metadata persistence, integrity quick_check, and fail-closed unknown-schema behavior
- Real WinUI 3 Foundation runtime host that initializes and verifies the same SQLite foundation used by later engines
- Runtime qualification evidence ZIP generated by the real WinUI host without including user document content

## Qualification requirements

Automated Windows qualification must prove locked restore, warnings-as-errors build, real Foundation tests, deterministic managed assembly hashes across clean rebuilds, self-contained WinUI publish, dependency-lock stability, and a clean repository after qualification.

Interactive Windows qualification must run the produced self-contained WinUI host on a real Windows 11 x64 user session and produce a runtime evidence ZIP reporting PASS for WinUI launch, SQLite schema, WAL mode, foreign keys, metadata round-trip, quick_check, and evidence generation. The runtime executable SHA-256 must match the exact host hash recorded by automated qualification.

## Non-negotiable constraints

Mocks, stubs, fake filesystem behavior, fake SQLite behavior, and placeholder product capabilities cannot satisfy this gate. Material changes to agreed architecture or launch scope require owner approval. Passing the gate cannot be achieved by removing, weakening, or deferring agreed v1.0 capabilities.
